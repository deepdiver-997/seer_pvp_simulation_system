# 技能判定流程与无效/效果失效体系

> 整理自设计讨论（2026-08-11）。本文是技能结算判定的权威口径，代码实现需对齐本文。
> 2026-08-22 更新：①澄清"攻击无法造成伤害"是独立的伤害层限制，**不阻断命中效果注册**；②穿透词条分级（无极圣武实测）；③新增第六节"固有效果的可否决性"（星皇之怒/强制执行实测）。

## 一、技能结算的三个阶段

玩家使用技能，命中判定按**固定顺序**分三个阶段：

```
阶段① miss 判定（最早，优先级最高）
  ↓ 若 miss → 技能无效（进入"无效"结果路径）
阶段② "无效"效果判定（次数类/回合类都算）
  ↓ 若无无效词条 → 命中
阶段③ "命中效果失效"判定（注册效果前）
  ↓ 若有 → 技能变白板/效果失效（补偿效果也不触发）
  ↓ 若无 → 正常注册技能效果 + 补偿效果
```

**关键顺序**：**先判命中（miss/无效）→ 再判命中效果是否失效**。
- 若对手只有"命中效果失效"，但你 miss 了且有补偿效果 → **补偿效果正常触发**，并跳过后面的命中效果检测。

## 二、"技能无效"层面（最常见）

所有导致"本次技能无效"的因素，结果相同：技能按无效处理，**若有补偿效果则触发**。

### 2.1 无效的来源

| 来源 | 判定方式 | 结果 |
|---|---|---|
| **miss** | 命中率判定失败 | 技能无效 |
| **狮盔** | 封攻击技能 | 攻击技能无效 |
| **龙威** | 封攻击+属性技能 | 攻击/属性技能均无效 |
| **封属** | 封属性技能（如米斯蒂克魂印） | 属性技能无效 |

> miss 严格说是"技能无效"的一种，只是判定方式不同（概率 vs 效果存在），**结果相同**。
> 例：南霜·大雪纷飞"若未命中则免疫下1次受到的攻击，免疫成功则令对手全属性+1"——"未命中"可以由 miss 触发，也可以由封属效果触发，都走同一补偿路径。

### 2.2 狮盔 vs 龙威

| | 狮盔 | 龙威 |
|---|---|---|
| 无效范围 | 攻击技能 | 攻击技能 **+ 属性技能** |
| 可否被"无视攻击免疫效果"穿透 | 分两种 | **不可**被"无视免疫"穿透 |

**狮盔的两种描述**：

1. **可穿透**：可被有"无视对手攻击免疫效果"词条的技能穿透。
   一般描述："免疫下一次/xxx回合内的攻击"。南霜·大雪纷飞的补偿效果就是这种。
2. **不可穿透（条件盔）**：带条件，无法被"无视免疫"穿透。
   - 坦普瑞·"禁术·契灭"："若消耗的PP值≥5点……额外令对手下1次攻击技能无效"
   - 不羁·弗里德·"天叶领域"/"余温之辰"："若下次对手使用的攻击技能威力大于120，则免疫此次攻击"

**龙威**：无法被"无视免疫"穿透。

**穿透词条分级**（2026-08-22 实测确认）：穿透不是布尔，而是**词条等级 vs 盔等级的比较**。无极圣武魂印虽列出一整张"无视"清单（能力提升效果、护盾承伤效果、攻击免疫效果），其中对"攻击免疫"的穿透只能穿**最低级的可穿盔**，条件盔/龙威照旧有效。后续遇到更高等级的无视词条（如可穿条件盔的）需单独收录等级。

盔侧等级（低→高）：可穿盔 < 条件盔 < 龙威。
攻侧词条：目前已知"无视对手攻击免疫效果"（含无极圣武的清单）= 最低级，只能穿可穿盔。

### 2.3 次数类的消耗判定

- **回合类**：自然减扣，回合减扣点统一减。
- **次数类**：一旦本次技能命中失败（miss 类），**会消耗所有可响应的次数类效果**。
  - 例：对手身上有一个"狮盔"，你发一次攻击技能但 miss 了 → miss 判定和"攻击技能是否有效"虽先后发生，但都属于攻击技能无效 → 狮盔**被响应并消耗**。
  - 对手有两个来源的次数"狮盔"各一个 → 一次攻击会**全部消耗掉**。

## 三、"命中效果失效"层面

**统一称"命中效果失效"**，两种表现形式：

1. **白板**（常见）：对手使用属性/攻击技能都不触发效果。
   - 属性技能：无伤害只有效果注册 → 什么都不发生。
   - 攻击技能：可能有两种——
     a. 和属性技能一样：不造成伤害，也不注册效果（= 威力为 0 的白板技能）
     b. 效果失效但**伤害照常结算**。
   - 代表：赤胆游龙·赵云魂印"胆"："自身每次登场后当回合免疫异常状态并令对手攻击技能的**附加效果失效**"——只是效果失效，基础伤害保留。
   - "白板"型（a）比赵云这种更常见。

**关键**：**"命中效果失效"级别的阻止，任何补偿效果都不触发。**

### 3.1 "攻击无法造成伤害"不属于命中效果失效（2026-08-22 确认）

"无法造成伤害"是**伤害层的独立限制**：伤害管线结算时把伤害归 0，但**命中效果照常注册生效**。

实战中它经常与"命中效果失效"**组合出现**（组合后既没伤害也没效果，看起来像白板），容易误以为它也阻断效果——判定时必须把两层拆开：

| | 效果注册 | 伤害 |
|---|---|---|
| 命中效果失效（白板 a） | 阻断 | 归 0 |
| 命中效果失效（保留伤害 b） | 阻断 | 照常 |
| "攻击无法造成伤害" | **照常** | 归 0 |

对应的官方规则佐证（`effect_des` 词典，见《官方数据关联查找指南》）：词条 318"免疫对手的攻击"明确层级为"计为无效 → 不计为命中 → 无法执行命中效果"——**效果阻断挂在命中/无效层，伤害归零挂在伤害层**，两层独立判定。

## 四、完整判定流程总结

```
使用技能
├─ ① miss 判定（优先级最高）
│   └─ miss → [技能无效] → 触发补偿效果 → 结束（跳过②③）
├─ ② 无效效果判定（狮盔/龙威/封属）
│   ├─ 无视词条等级 ≥ 盔等级？→ 穿透 → 命中
│   └─ 被无效（含 miss 类）→ [技能无效] → 消耗可响应的次数类 + 触发补偿效果 → 结束
├─ ③ 命中效果失效判定
│   ├─ 白板（a）：无伤害无效果
│   ├─ 效果失效（b）：伤害照常，效果不注册
│   └─ 正常：注册效果
├─ ④ 伤害层（与③独立，见 3.1）
│   └─ "无法造成伤害" → 伤害归 0，已注册的命中效果不受影响
└─ 命中 → 注册技能效果 + 补偿效果 → 伤害管线结算
```

## 五、代码实现：技能无效中心（SkillInvalidCenter）

现状：`Skills::query_usage` 返回 `{ OK, MISS, SEALED }`；`BattleContext::skill_seals[2]` 只有次数类拦截桶。
不足以承载本文的无效体系。重构方案如下。

### 5.1 统一结构：SkillArmor（替代 skill_seals）

盔/威/封属统一为一条"无效记录"，挂在**被无效方**身上（挡对方技能）：

```cpp
struct SkillArmor {
    enum class Kind { SEAL_ATTACK, SEAL_ALL, SEAL_ATTRIBUTE };
    // SEAL_ATTACK   = 狮盔（只封攻击技能）
    // SEAL_ALL      = 龙威（封攻击+属性技能）
    // SEAL_ATTRIBUTE= 封属（只封属性技能）

    Kind kind;
    int remaining_rounds = 0;  // 回合类窗口（>0，回合减扣点统一减）
    int remaining_counts = 0;  // 次数类（>0，响应即减）
    bool penetrable = true;    // false = 条件盔/龙威，不可被"无视攻击免疫"穿透
    int source_id = -1;        // 注册精灵实例句柄（槽位+队伍，非 pet.id）
    // 条件盔的条件（如"威力>120"）；nullptr = 无条件
    // 条件判定提前到操作阶段看技能面板威力，不等伤害结算
    std::function<bool(BattleContext*, int attacker, int defender)> condition;
};

enum class InvalidBinding { SELF, TEAM };
// SELF = 绑定自身，下场时清理（如南霜"免疫下1次受到攻击"）
// TEAM = 绑定全队，切换保留（队伍被动）

struct InvalidEntry {
    int owner;               // 被无效方 (0/1)
    SkillArmor armor;
    InvalidBinding binding;
    int source_slot;         // 注册精灵槽位（绑定自身时下场清理用）
};
```

### 5.2 核心：SkillInvalidCenter（事件中心变体）

```
用法（对齐玩家确认的"全部消费"语义）：
  使用技能时 → notify(attacker, skill_category, power, ignore_immune)
  → 中心匹配所有"响应此技能"的条目，无条件各减一次次数：
     - 条件不满足 → 跳过（保留）
     - 可穿透盔 && 技能带"无视免疫" → 穿透跳过（保留，A方案）
     - 响应 → remaining_counts--，减到 0 注销
  → 有任一响应 → 技能无效（触发补偿）
```

**全部消费**：一次技能使用会消费**所有响应它的次数类条目**，不因某个盔/龙威挡了另一个就保留次数。例：
```
对手身上：1次属性无效 / 3回合属性无效 / 无条件盔 / 3回合龙威 / 1次龙威
我方用攻击技能 → 无条件盔、1次龙威各减1；3回合龙威响应但不减（回合类）；
                封属性的两条不响应（只封属性），不动。
```

**唯一标识**：同一注册精灵（source_slot）的同类条目合并计数。例：精灵A给全队注册2次属性无效 + 精灵B自己注册1次属性无效 → 对手用一次属性技能 → A条目 2→1，B条目 1→0 注销。

### 5.3 切换保留

- **SELF**：换宠流程（`OPERATION_ENTER_EXIT_STAGE`）中，对下场精灵，清理它注册的 `SELF` 条目。
- **TEAM**：切换保留，直到自然到期。

### 5.4 判定顺序（对齐第三、四节）

```
Skills::query_usage(ctx, owner):
  ① miss 判定（最高优先级）
     → 若 miss：仍 notify 中心（miss 也消费可响应的次数类）→ 返回 INVALID
  ② 命中：notify 中心 → 有响应 → INVALID（触发补偿）
  ③ 无无效：查"命中效果失效"（防御方）
     → 白板(WHITEBOARD)：伤害归0 + 不注册效果（EFFECT_BLOCKED）
     → 保留伤害(KEEP_DAMAGE)：伤害照算 + 不注册效果（赵云"胆"）
     → 无 → OK
```

- 命中效果失效的伤害归零在**伤害管线结算**时看标记执行（白板抹零，保留伤害不动）。
- "无法造成伤害"同样只在**伤害管线**处理（伤害归 0），**不影响效果注册**——与命中效果失效是两个独立开关，可单独存在也可叠加（见 3.1）。
- 补偿效果：`INVALID` → `SKILL_INVALID` 分支触发；`EFFECT_BLOCKED` → 不触发任何效果（含补偿）。

## 六、固有效果（选择期效果）的可否决性

固有效果在技能选择期触发、天然不受 miss 影响。但**能否被各层无效体系废掉是逐效果的属性**，不能从"固有"这个类别推导——同类固有效果在"命中效果失效"面前的表现不同：

| 效果 | miss / 技能无效层 | 命中效果失效层 | "无法造成伤害" |
|---|---|---|---|
| 条件先制（如 1002"对手处于异常状态则先制+1"） | 选择期已结算，正常生效 | **仍生效** | 不影响 |
| 南霜·大雪纷飞的"未命中"补偿 | 触发 | **被阻断** | 不影响 |
| 瀚宇星皇·星皇之怒（固有效果："技能无效时 50% 额外行动"） | **触发**（miss 与技能无效层均允许） | **不触发** | 不影响（其本体是额外行动，非命中效果） |
| 无为觉者·强制执行（PP=0 技能：必定命中 + 强制执行命中效果） | — | **无视命中效果失效** | **同时无视"无法造成伤害"**（2026-08-22 实测） |

结论与实现口径：

1. 可否决性做成**效果元数据标签**（`hit_effect_invalidatable` / `invalid_compensatable` 等），数据来源优先对齐官方 `effect_icon.kind` 分类（游戏内固有/命中效果图标不同即此分类的 UI 体现）。
2. 引擎按标签过滤分支节点，不做类别级一刀切——`is_hit_effect_invalid` 命中时，只跳过带 `hit_effect_invalidatable` 的节点。
3. 强制执行是"请求携带通行凭证"方向的极端案例：执行请求带 bypass 掩码，过门时查凭证。`must_hit`（必定命中，官方词条 312）是同族的最小成员，宜一并纳入统一的凭证体系。

## 七、机制记录：暴击重置防御等级（待接入）

> 2026-08-22 用户游戏实测确认。与当前效果主线关联不大，先记录在案。

**规则**：使用攻击技能时，除非 miss，否则**只要触发暴击就重置对手相应防御正等级为 0**——不管命中效果是否被无效、不管对方有没有狮盔。

- 判定位：特殊攻击暴击 → 对手的**正特防等级**归 0；物理攻击暴击 → 对手的**正防御等级**归 0。
- 只清**正等级**（提升过的防御），负等级不动；能力下降之类不在此列。
- 触发时机在命中层（独立于"命中效果失效"与"无法造成伤害"两层）。
- 待接入点：暴击结算处（DamagePhase 致命值 / crit 判定后）追加"重置对应防御正等级"。

## 八、设计方向（2026-08-22 讨论中，未定稿）

**典型案例：希拓「烬灭神咒剑」37218**（side_effect=[2000, 1287, 2126]，一次包含三种触发形态）：

| effect | 模板 | 触发形态 |
|---|---|---|
| 2000 | 若对手处于能力提升状态则先制+1且必定命中 | 选择期条件先制 + 必中凭证 |
| 1287 | 吸取对手能力提升，**吸取成功则**下{0}次受到的攻击伤害减少{1}% | 主效果返回值驱动分支（吸取成功与否） |
| 2126 | **技能无效时**，消除对手回合类效果、能力提升效果，令对手焚烬 | 事件触发（技能无效补偿） |

**讨论中的方向：效果组合单元语法**。效果不再是一层扁平函数指针列表，而是"单一条件效果单元"组合：

- 单元 = 主动作（原语调用）→ 返回值 → if-else 分支（可能嵌套）。
- 例：`吸取对手200点体力，若吸取少于[预期]则改为附加200点真实伤害`、`全属性+1，若XXX则翻倍（全属性+2）`。
- 三种 if 形态映射到现有引擎：选择期前置条件（`selection_effects_`）、返回值后置条件（需新增结果槽通道，`EffectResult` 目前只有 kOk/kSkillInvalid/kHitEffectInvalid 三个粗码，`apply_anomaly` 的 TARGET_IMMUNE 等细码在函数边界被丢弃）、事件触发（watcher）。
- 好处：Type B 补偿（"施加异常/吸取体力被天生免疫挡住"）自然化解为效果自身的 if-else 分支，不需要独立补偿表。

**凭证放 workspace 的结论（已验证）**：`BattleWorkspace` 每回合在 `handle_BattleRoundStart` 开头 `reset()`（battleFsm.cpp:683），"下一回合自动刷新"成立 → 本回合内穿透凭证可直接放 `ws` 字段，回合结束自动清，无需手动销毁。**多回合/次数授予**（"下N回合无视"）仍需走效果桶生命周期，攻击时并入凭证。详细讨论见 git 对话记录。
