## 二、核心架构决策：效果从"一函数一效果"重构为"原语 + 数据程序"

**现状模型**：`include/effects/effect.h` 的 `EffectFactory` 按 effect_id 从动态库注册 `EffectFn`（1 effect_id = 1 个函数）。

**数据事实**：2101 条 effect_info **几乎全部是独特的复合描述**（例如"获得护盾，护盾消失时造成固定伤害且使自身下2次攻击伤害翻倍"）。按现状模型 = 写 2101 个函数，不可行。

**目标模型**：

1. **原语库（100~300 个通用函数）**：扣血、治疗、能力增减、护盾获取、异常施加、断回合、反弹、固定伤害、净化、下次攻击buff、控场/免控……每个原语是可参数化的模板函数。
2. **每条 effect_info → 一条"效果程序"数据**：`[(原语id, 参数, 触发时点, 条件)]`。

**现有可复用机制**：`include/entities/skills.h` 的 `SkillEffectNode` 已有 `registerState` + `usePendingTrigger/pendingObserveState/pendingTtlRounds`——"护盾破盾回调"这类延迟触发已经能被这个机制承载。

**收益**：AI 批量干的活从"写函数"变成"转数据"，2101 条从代码变成数据。这是让 AI 高速编码从不可行变可行的钥匙。

## 三、AI 生成工作流：防乱实现的校验阶梯

原理：**不靠信任，靠三级校验**。AI 批量干的部分不逐条问人（2101 个阻塞问题不可行）。

1. **第一级 · schema/语义自动校验**（机器查）：效果程序必须引用合法原语 id、参数范围合法、目标合法。能自动挡掉结构性错误。
2. **第二级 · 黄金集 + 差分/行为测试**：先人工确认一小批黄金效果（例如 100 条）；AI 批量转完后**必须能完全正确还原黄金集**（能→大概率整体正确），再跑已知交互的行为测试（某技能必须产生某结果）。
3. **第三级 · 置信度门槛的 flag 队列**：AI 自检把低置信项标出，**每条附"为什么这么转、备选方案是什么"**，人工只审这个异常队列，不审全量。

**思路/说明的分配原则**（回答"给思路会不会太多"）：

- 原语函数（100~300 个）：**必须给设计说明**——它们定义语义，值得审。
- 数据实例（2101 条）：**不给逐条思路**——用自动校验+黄金集替代"解释"这个动作。
- flag/歧义项：**必须带推理**。

**预期与边界**：清晰描述的大部分能自动转对（估 60~80%），黄金集+flag 兜住其余；部分效果从文本不可判定 → 需要进游戏实测。官方描述不清、版本常改 → 黄金集要维护、训练目标不是"完美还原官方"而是"**自洽到能跑训练**"。

## 四、落地顺序

1. **重构效果层为"原语 + 数据程序"**（开启一切的钥匙，先定义效果程序的数据格式）；
2. **AI 写原语库**（带设计说明，人审）；
3. **挑一小片阵容做黄金集**，批量转码，跑通校验阶梯；
4. **接 FSM + sim_training_cli 跑通自博弈 MVP**（枚举 + 单回合精确结算 + 简单价值函数，早期决策用手写打分 + ε-greedy，不用纯随机）；
5. 扩充内容（增量数据工作）。

## 五、与训练路线的衔接（详见 `docs/AI决策框架与训练思路.md`）

- 效果正确性 = 模拟器正确性 = 自博弈地基（垃圾模拟器 → 垃圾策略）。
- 训练数据 = 决策点的 `(状态向量, 合法动作掩码, 动作, 回报)`，**不是**所有时点的快照。
- 状态特征由模拟器产出：全局块 + 每精灵块 + 每合法动作的计算特征（期望伤害/控制成功率）。**引擎能算的都算成特征，网络只学算不动的（远期价值）**。
- 克制关系不手教：属性进特征，让它从数据自己学。
- 硬约束（关键精灵不能死）用过滤/词法优先级，不用权重。
