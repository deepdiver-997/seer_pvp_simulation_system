# 官方数据关联查找指南

> 整理自 2026-08-22 的数据考古。目标：**任何 agent（或人）拿到一个精灵名/专属名词，都能不问自答地查全它的机制定义**。
> 配套工具：`scripts/tools/query_seer_term.py`（本文所有工作流的命令行封装）。

## 0. 核心教训：专属名词必须递归查词典

现代精灵的魂印/技能描述大量使用**专属名词**（如"骑士决斗""永沐""帝君之罚"），名词本体定义不在描述文本里，而在 **`effect_des` 词典表**中。

典型案例：星光·艾欧丽娅（4911）的魂印只写"为双方附加骑士决斗"，而**技能转换机制**藏在词条定义里：

> 骑士决斗：进入时，自身解除所处的异常状态且**对手下次使用的技能转化为其的第五技能**；自身没有可选择使用的第五技能时无法行动；自身死亡、主动下场时，骑士决斗转化为骑士决斗·落败……

**规则：读任何魂印/技能/效果文本时，先问"里面的名词有没有正式定义"，有就递归查 `effect_des`，否则一定会漏机制。**

而且 `effect_des` 不只收状态名词——它同时是**官方机制与规则词典**：

| kind | 内容 | 例子 |
|---|---|---|
| 1（412条） | 专属名词/状态类词条 | 骑士决斗、百步穿杨、毒苹果、危机感 |
| 2（46条） | 异常状态定义 | 中毒、麻痹、睡眠、诅咒 |
| 3~5（~95条） | **机制/时点术语** | 执行、转化、反转、先制、必定命中、回合类效果、固定/百分比/真实伤害、回合开始时、战斗阶段结束时、被击败、击败、额外行动、异常状态附加效果 |

kind=3~5 对引擎实现直接有用，几条关键正式定义：

- **执行**（328）：效果结算 = 满足触发条件 → 通过概率判定 → 未被其他效果中断 → 触发；否则执行中断。
- **免疫对手的攻击**（318）：被免疫的攻击计为无效 → 不计为命中 → 无法执行命中效果。**官方自己给出了无效/命中的层级语义**。
- **回合类效果**（313）：后出手附加时若当回合无法直接触发收益，回合数+1。
- **战斗阶段结束时**（317）：先手方行动结束后任一方死亡 → 战斗阶段中断，不触发战斗阶段结束效果。
- **异常状态附加效果**（337）：效果中的最小子类——概率阈值类魂印（帝皇铠甲/梅赫维特）检测的就是这个子类。

## 1. 数据库

| 库 | 状态 | 说明 |
|---|---|---|
| `scripts/data/processed/seer_unity.sqlite` | **当前使用** | Unity 端迁移后的数据，C++ 运行时默认读它 |
| `scripts/data/processed/seer_official.sqlite` | 旧版参考 | 官网抓取版；`query_monster_profile.py` 默认指向它，但缺新精灵 |

注意：`query_monster_profile.py` 对 unity 库不兼容（`sp_hide_moves.itemtips` 列缺失会报错），且对旧库也查不到新精灵。**优先用 `query_seer_term.py`**。

## 2. 表速查

| 表 | 内容 | 关键陷阱 |
|---|---|---|
| `monsters` | 精灵基础信息 + `raw_json` | **`soul_mark_id` 全为 0，是死列**；魂印不走这里 |
| `monster_learnable_moves` | 精灵↔技能关联（monster_id, move_id, learning_lv） | **唯一可靠的技能关联表** |
| `moves` | 技能静态数据；`side_effect` 存 **effect_info 的 id 列表**；`side_effect_arg` 是按序展开的扁平参数表 | `moves.mon_id` 覆盖不全（只到 4706），**不要用它反查精灵** |
| `effect_info` | 技能效果模板库（`info` 带 {0}{1} 占位符，`args_num` 参数个数） | |
| `side_effect` | 仅存每个 effect 的参数个数（`arg_count`） | 不是效果定义表，别和 moves.side_effect 列混淆 |
| `effect_icon` | **每精灵魂印**（`pet_id` 为 JSON 数组字符串如 `"[4911]"`） | `pet_id LIKE '%4911%'` 会误中 14911，**必须 JSON 解析后精确比对**；`tips` 含富文本标记需清洗 |
| `effect_des` | **专属名词 + 异常状态 + 机制/时点术语词典** | 见第 0 节 |
| `new_se` | 刻印/特性效果库（idx 即 stat 类 id） | 只有 400 条，非每精灵数据 |
| `sp_hide_moves` | 第五技能解锁展示表 | |
| `battle_effects` / `boss_effect_icon` / `buff` | 战斗效果名/图标分组 | |

## 3. 四条标准工作流

### 3.1 精灵名 → 魂印（含专属名词展开）

```bash
python3 scripts/tools/query_seer_term.py --name "星光·艾欧丽娅" --expand
```

等价 SQL（魂印本体）：

```sql
SELECT effect_id, kind, args, tips FROM effect_icon
WHERE pet_id LIKE '%4911%';   -- 仅快速人肉过滤，精确判定要 JSON 解析 pet_id
```

### 3.2 专属名词 → 定义

```bash
python3 scripts/tools/query_seer_term.py --term "骑士决斗"
```

等价 SQL：

```sql
SELECT id, kind, kinddes, desc FROM effect_des WHERE kinddes = '骑士决斗';
-- 或模糊：WHERE kinddes LIKE '%骑士决斗%'
```

### 3.3 精灵 → 技能 + 效果模板渲染

```bash
python3 scripts/tools/query_seer_term.py --pet-id 4808 --with-moves
```

手工渲染规则（工具已内置）：

1. `moves.side_effect` 如 `[1002, 191, 47]` → 逐个查 `effect_info.id`；
2. `side_effect_arg` 如 `[1, 4, 4]` 按每个效果的参数个数（`side_effect.arg_count`，缺省用 `effect_info.args_num`）切片消耗；
3. 模板 `{0}` `{1}` 用切片参数填充。

### 3.4 名字 → 精灵 id

```sql
SELECT id, name FROM monsters WHERE name LIKE '%米修莉%';  -- 先模糊找形态
```

同名多形态/皮肤时用 `--pet-id` 精确指定。

## 4. 检索路径总结

```
精灵名 --(monsters.name)--> 精灵 id
  ├─(effect_icon.pet_id JSON精确匹配)--> 魂印 tips
  │      └─(文本中的名词 --effect_des.kinddes 最长优先)--> 专属名词/机制术语定义（递归）
  └─(monster_learnable_moves)--> 技能 id列表
         └─(moves)--> side_effect[] = effect_info id 列表
                └─(effect_info.info + 参数切片)--> 效果模板渲染文本
                       └─(模板文本中的名词)--> effect_des 定义（递归）
```

## 5. 已知机制实证索引（考古结论备查）

用这套流程验证过的机制结论，供后续实现对照：

- **技能转换（保留先制/PP 的覆盖式）**：骑士决斗词条（effect_des 524）——"对手下次使用的技能转化为其的第五技能"。转化（310）有正式定义：**不受"附加/受到"类效果响应**。
- **概率阈值废除非效果**：帝皇铠甲/梅赫维特魂印（effect_icon 4930/4853）——检测目标为"异常状态附加效果"（effect_des 337 的最小子类）且概率 ≤50%。
- **场下魂印抑制场下→场上指定**：薇尔诗（4000）"双方场下的精灵无法指定场上精灵为效果对象"；帝皇铠甲会**检测并惩罚**这种被阻止的指定（水之掩藏）→ 拦截必须是带事件的否决。
- **强制执行**：无为觉者（4661）"PP=0 的技能必定命中、强制执行命中效果"；实测还无视"无法造成伤害"。配套词条"执行"（328）给出了官方结算管线。
- **改写技能效果定义**：万相乖离（4661）"永久取消第五技能首条未取消过的效果中的触发条件并提升50点威力"。
